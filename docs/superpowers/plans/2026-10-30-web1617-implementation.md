# 保存済みWeb 1.6.17画面のAndroid・PWA接続

利用者は画面・タブ配置・デザインの変更と、別会話で作成した画面の利用を明示済み。再提案・再承認を前提にせず、[固定した画面・部品・文言](2026-10-30-web-1617-design-baseline.md)を実装する。以前の就寝中のUI変更保留は解除されている。`plan.txt` / `add.txt` は変更しない。

## 接続範囲

- 地図／一覧／対応／安否の4タブ、設定はメニュー。保存済みの色・一覧行・詳細シート・入力部品を基準とする。グループ作成・招待参加は利用者が選んだ画面3を維持。
- 実際の記録から人物・通報・担当・対応状況・緊急度・資材・活動状況・自分の安否とメモを表示、保存、共有する。
- 対応予定を含む4段階、通報の訂正・取消・復元、取消理由と履歴、地域ID、CSVの日英文言を記録層へ接続する。氏名・住所・自由文を翻訳しない。
- 地図から通報地点を選ぶ。人物の現在位置に登録住居を代用しない。匿名期間と住居の表示条件を固定画面の条件に合わせる。
- 0〜35m・1m刻みの検証済み計算結果を地図で読み込む。新しい数値データは36条件すべての検証後に配布する。

## データ互換

新しい通報属性の既定値は旧記録へ自動追加しない。既存イベントIDと内容の対応を保持する。取消・地域情報・対応予定を含む記録を旧端末が意味を落として保存しないよう、Cloud通信は対応バージョン2の明示、Nearby通信は該当対応記録にwire v10を使用する。更新が必要なCloudクライアントには426を返し、取得位置の進行や保存確認を行わない。旧形式だけのグループは従来どおり取得できる。

## 未実装の権限・データとの境界

見本の立場切替・模擬時刻・架空住民は製品へ移植しない。現行のグループ作成者が管理者、招待参加者が一般メンバーという権限を使う。実際の他町内会連携・自治体職員の認証・共有地域設定がない状態で、市全域統計や地域一覧を架空データで補わない。これらの接続は4画面の移植完了とは区別して残す。

## 検証記録

Cloud/クライアントの対象試験50件で、取消・復元・対応予定のサーバー再起動後の保持、旧形式への対応、取得位置の保全、v10の中継を確認した。その後Webの全ロジック試験155件と、生成済み36条件ファイルの存在試験1件（合計156件）、Cloudの31件と配布Worker試験1件（合計32件）が成功。Cloud試験には実Worker実行環境・SQLiteの再起動とグループ分離も含む。

新PWAのブラウザー試験は実Storeを使い、案件・担当・進捗・資材の保存、安否メモの再起動後保持、取消復元、言語切替、400px／320px表示を確認した。階数未登録・寝室のみの情報が一覧から消える不具合を修正し、3分前の非表示と公開後の表示を追加確認した。比較ページはmain `92c0b8a` で公開済み。

PWA1.6.1を既存Cloudflareへ公開し、公開先の独立2ブラウザーで招待参加・訓練・通報・対応予定・資材・取消復元・圏外再起動と再送・管理者終了を確認した。旧1.6.0からの更新試験でも同じ端末ID・グループ・活動名・住居・安否を保持した。`output/playwright/cloud-pwa-1.6.1-public/verification.json` と `output/playwright/pwa-upgrade-1.6.1/verification.json` を証跡とする。これは実iPhoneでの新版確認の代替ではない。

最終レビューで、編集中のフォームに別端末の更新が届くと保存時に新しい親記録を選んでしまう箇所を発見。フォームを開いた時点の親記録を固定し、既存の同時更新・古い編集の検証を維持する修正を完了。進捗・緊急度・担当・取消・活動の5種類で、未表示の新しい記録を保持し古い編集を拒否することを確認した。`output/playwright/pwa-stale-edit/verification.json` に記録。cache r16で再公開し、`output/playwright/cloud-pwa-1.6.1-r16-public/verification.json` で公開共有操作も再確認。
