# 住所正規化・座標取得・建物対応の再評価

調査日: 2026-11-02。状態: 調査・実測済み、以下の統合構成は提案。公開版への導入完了を示すものではない。

## 結論

無料、PCの常時稼働不要、Android/PWA共通、登録結果の保存、オフラインという条件では、**公的住所データを補完して市単位の検索データを配布する方式**を第一候補とする。地図の背景を替えるだけでは住所検索の問題は解決しない。

- 正規化: Geoloniaの日本語住所正規化を評価基準・候補とし、市区町村の省略補完を追加する。
- 座標: アドレス・ベース・レジストリ（ABR）に国土交通省の位置参照情報（ISJ）を追加する。出典と座標の粒度を保つ。
- 施設名: PLATEAUの収録名称、自治体の公開施設一覧など、再配布できる名称・住所・座標を別索引にする。必要に応じてOSM由来の施設検索を追加評価する。
- 建物: 検索地点へ移動し、PLATEAUの建物形状から選択・ピン調整して確定する。街区代表点から最寄りの建物を無条件に確定しない。
- 配信: 既存の市別地図配信と同様に、公開データの索引を既存の配信先から取得・端末保存する。全住所を毎回外部APIに問い合わせる構成を避ける。

全国の建物名を網羅する無料検索を、この構成だけで実現できたとは言えない。まず京都市、港区、熱海市で検索の一致率・位置精度・データ量を測り、施設検索の不足分を判断する。

## 実測で分かったこと

テストは8入力をJageocoder開発元デモ、CSIS、地理院住所検索、Geolonia 3.1.3に各1回、計32条件で行った。外部HTTPの3系統は直列に間隔を空けて利用した。Google等のAPIキーが必要なサービスは資料比較のみ。少数の例による比較であり、全国精度のランキングではない。

### 讃州寺町203の詳細

現在取得済みのABR由来データにも203という地番はあるが、その行の座標が空である。現行の索引生成は座標のない地番行を除外するため、検索できない。「他のデータを使っても検索不能」ではない。

国土交通省の2025年データ24.0a、京都市左京区CSVを直接取得し照合した。

- 203の座標: 緯度35.011046、経度135.774524。
- 讃州寺町52行に対して座標は3種類。
- **203を含め25行が上記と同じ座標**。192、193、198、200、202、206等にも同じ点が付く。
- Jageocoderの結果は上記と一致。CSIS・地理院は丸めの異なる近接点。同系統の元データなので、三者一致を独立した精度保証として扱わない。
- Geoloniaでは住所の認識レベル8に対して座標のレベルは3。住所が最後まで一致しても建物の座標を取得できたとは限らない。

ISJ公式説明は、住居表示未実施地域では街区相当の範囲内の地番を共通代表点へ対応付けすると明記している。したがって、この点を203の建物中心と呼ばず、付近へ移動するために使う。

取得元: https://nlftp.mlit.go.jp/isj/dls/data/24.0a/26103-24.0a.zip

SHA-256: `711ac95425630751274fad78c9571686b3205d3f6d978511ffcf6a0246d0fde0`

規約比較は一般的な注意喚起ではなく、「検索結果を登録住居として保存し、圏外でも他端末へ共有できるか」という機能要件の比較である。無料の地図画面で検索できることは、その検索データをアプリへ保存・再配布できることを意味しない。

## 推奨する処理とデータ設計（未実装部分を含む）

1. 元の入力を保持し、全角数字、ハイフン、番地・号表記等を正規化する。丁目等の数字と固有の町名を無差別に置換しない。
2. グループ活動地域を検索の補助に使う。「左京区…」なら京都市を補完するが、明示した他市の住所は書き換えない。
3. 住所索引と施設名索引の候補を一つの検索欄で表示する。丁目だけの候補を完全住所一致として扱わず、先頭候補への無条件決定をやめる。
4. ABRの適切な座標を優先し、欠損はISJ等で補完する。単に細かい番地ラベルがあるだけで座標精度を引き上げない。同精度の競合も出典を残す。
5. 選んだ地点へ地図を移動し、ピン・建物選択で住居を確定する。最終座標を含むPLATEAU建物を候補にし、形状が重なる場合等は利用者が確認する。
6. 建物が未収録でも住所と確認済み位置を登録可能にする。無関係な近隣建物へ強制的に対応付けない。
7. 市別データに版・出典・チェックサムを付けて配布。Android/PWAで同じ検索用データとテスト例を使う。

保存項目は、元入力、正規化した住所要素、公的住所ID（存在する場合）、検索結果の住所一致粒度、検索点の粒度・出典・版、本人が確認したピン、PLATEAU建物ID・データ版、階・部屋を分ける。住所文字列の変更だけで古い建物IDが残らないようにする。

逆引きも同様に、最寄りの地番をその建物の正確な住所として表示しない。確認できた住所まで表示し、番地の確証がなければ本人に確認・入力してもらう。

会場デモの架空割当は、PLATEAU建物内へ位置を割り当てることと、その建物の正確な郵便住所を知ることを区別する。実住居とデモ住居を別の記録として保持し、設定で変更したデモ住居と地図の割当建物を同じ記録から表示する。

## 実装前後の検証項目

- 203、全角203、府市省略、京都の通り名、存在しない番地、京都タワー、六本木ヒルズ、熱海の住居番号を含む固定テスト。
- 番地認識と座標精度を分離。広域部分一致を検索成功の件数へ混ぜない。
- 市ごとの収録率、建物内部に入る点の割合、確認用正解との距離を別々に集計。今回の8例から市全体の精度を推計しない。
- 地図移動→ピン調整→建物変更→登録→再起動→端末間同期の対応関係をAndroid/PWAで検証。
- ダウンロード済み市で圏外検索。索引未保存時と施設名未収録時の動作確認。
- 最大40人の初回ダウンロード、端末での検索時間、データサイズ、既存クラウド無料枠の使用量を計測する。無料公開データだからホスティングも無制限とはしない。
