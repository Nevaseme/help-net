# 設定パネルの操作と住居検索の修正（2026-11-01）

## 原因

- Androidは設定を開いた状態でメニューを設定の裏に開いていた。PWAはヘッダーが inert とスクリーンで操作不能になり、長いパネルもヘッダーへ重なっていた。
- パネル上端の横棒は両版とも装飾で、閉じる操作を持たなかった。
- 「住所・建物名で絞り込む」は登録済みのグループ建物だけを対象としていた。住所から建物を探す計画に対し、入口では公開住所・施設を検索できない不一致があった。
- vivoの実際の活動市は熱海市（22205）だった。活動市による検索制限も、京都の検索語が出ない原因となった。活動市は変更せず、京都・熱海の収録済み索引の横断検索へ修正した。

## 実装

Android 1.5.42 / PWA 1.6.16。メニュー操作時に設定などのパネルを閉じ、メニューを切り替える。ヘッダーと下部ナビを操作可能なまま残す。横棒は操作領域を確保した閉じるボタンになり、下40dp（Web40px）を超えるドラッグでも閉じる。本文のスクロールは閉じ操作にしない。以前の振動・フリーズを避けた静的パネル配置を維持する。

住居一覧の「住所・建物名で探す」で公開住所と施設名を検索する。入力250ms後に検索し、古い入力の結果を表示しない。グループ内の登録済み建物は別に表示。候補選択後に地図で建物を確認し、施設名は建物名へ、住所候補は住所へ設定する。施設名を住所として保存しない。元の手動登録も維持する。

住所は既存ABR系データ、施設は取得済みOpenFreeMap/OpenMapTiles/OSMの名前付きPOIを使用。京都24,287件（gzip658,482 bytes）、熱海697件（18,500 bytes）。全施設を網羅するものではない。端末に存在しないデータを補完して候補を捏造しない。新しい外部サービスは追加しない。

Androidは両市の索引を同梱。PWAは市全域保存に施設索引を追加。保存済み市の検索は圏外再起動後も使える。市全域を保存し直す際は古いメタデータも更新し、Service Workerが更新用リクエストを古いキャッシュへ戻さないようにした。活動地域の範囲と検索対象を分け、検索結果側の市を建物輪郭の選択にも使う。

## 検証

- Android JVM250件、JavaScript166件成功。
- Androidの横棒タップ・下スワイプと同梱索引検索の2試験がエミュレーターで成功。
- 通常画面テストがエミュレーター・vivoで成功。メニュー→設定→メニュー→閉じる、横棒タップ、左京区検索、京都タワー検索、候補選択→地図を確認。vivoは活動地域が熱海のまま成功。vivo最終実行18.937秒、エミュレーター最終28.777秒。
- 試験の初期失敗は候補表示前に入力欄を押していたこと、起動順序、活動地域限定をそれぞれ区別した。通常アプリのデータ削除・端末再起動は行っていない。
- 公開PWAの専用ブラウザーで、上記操作、下スワイプ、熱海所属の京都検索、施設名を住所として登録しないこと、空の検索結果を確認。旧メタデータを保存した状態から市の保存を更新し、完全通信遮断・再読み込み後に京都タワー検索が成功。iPhone実機の今回の操作試験は行っていない。
- 最終公開Worker deployment: `2cc781edef02452e9f42c7b2d4b5c9ab`、SW `r38c-menu-search`。GROUPS保存領域と既存バインディングを維持。
- 公開画像は架空グループのエミュレーターと専用ブラウザーのみ。vivoの画像・保存データは公開していない。

証拠は `.implementation/menu-search/` とローカル visualizations の `menu-search-1542/`。利用者管理のplan.txt/add.txtは変更しない。
