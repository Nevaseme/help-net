# Androidの圏外中継とクラウド復帰

## 対象と確定事項

会場デモの通信整備として、Android Aが圏外で保存した安否・通報をAndroid Bが預かり、Aがその場を離れていてもBのネット復帰後に既存Cloudflareへ送れるようにする。PWA Cはサーバーから自動取得する。元作成者・記録ID・内容は維持する。

利用者の追加指示により、Wi-Fi無線を完全OFFにする必要はない。本番はモバイルデータOFF、インターネットにつながる会場APから切断して自動再接続を止め、Wi-Fi無線とBluetoothはONとする。新しい常駐PC・有料プラン・別の外部サービスは追加しない。

## 既存試験から言えること

Xiaomi／vivoの1.5.22試験は近距離の自動接続、切断中のプロフィール保存、再接続後の同一記録保存の実証。XiaomiはWi-Fi ON・AP未接続・ネット接続なし。これを全会場シーンの検証済みとは扱わない。20台試験は仮想通信路上の処理試験であり、20台の実無線試験ではない。

## 実装

- AndroidKeyStoreで作成したP-256鍵の公開鍵を、オンライン時に本人のグループ資格情報で登録する。秘密鍵を他端末やサーバーへ渡さない。
- オフライン記録の元JSONとグループ・記録種別へ署名し、通常のNearby同期に加えて署名付きの原本を交換する。分割送信・再送・端末内保存により、受信端末の再起動後も中継できる。
- サーバーは登録済みの元作成者の鍵で検証する。中継者の権限を元作成者へ付け替えず、管理者操作には元作成者の管理者権限を要求する。署名なしの他人の新規記録は引き続き拒否する。
- Roomを7から8へ移行し、署名原本用テーブルを追加。既存データベースを作り直さない。サーバーも既存のDurable Object namespaceと記録を保持する。
- 端末内の保存・近距離からの保存済み受信をWorkManagerの自動送信へ接続する。既に送信処理中なら後続を1つ確保し、連続受信で仕事を無制限に積まない。
- 成立根拠より成立記録が先に来る、元通報より訂正が先に来る場合は、他の記録の保存確認が進んだときだけ保留分を同じ同期内で再送する。成立情報がまだ届いていないことを示す特定の409応答は、バックグラウンド再試行を維持する。恒久的な権限不足・署名不正・内容競合による無限再送にはしない。
- PWAは`pageshow`でも再同期の周期を復帰させる。`online`、前面復帰、15秒周期の再試行を使い、共有ボタンの押し直しを不要にする。iOSが停止したPWAの完全無操作実行は保証対象にしない。

## 利用前の条件

各Androidは更新版で一度オンライン同期し、本人の公開鍵・最新名簿・開始情報を取得してからオフラインへ移る。旧版で署名を作っていない記録を、中継端末が本人の代わりに署名することはできない。PWAの圏外操作はそのPWA自身に保存され、PWA自身のインターネット復帰後に送信される。

Androidが1台だけネットに戻れば、その端末が既に預かった有効な記録はクラウドへ届けられる。受け取っていない記録まで取得できるという意味ではない。Androidの電池制御・OSの仕事の実行時期による遅延は残る。

## 検証状況

- 公開PWAで独立2ブラウザーの自動参加同期、圏外SOS・通報保存、ネット復帰後の自動送受信、onlineイベント欠落時の周期復帰、応答消失後の重複なし再送、処理中の通信復帰、圏外再読込を確認。共有ボタン操作は0回。pageshow試験はイベントを明示的に発火した確認で、実際のBFCache採用確認ではない。
- `RelayHttpsTest`：エミュレーターの本物のAndroidKeyStore・Room・SharingSession／SyncEngineを使い、Aが圏外で作った安否回答と通報をBへ渡し、Aを停止、BのDBを閉じて再読込し、Bが公開HTTPSへ元作成者の記録を送るところまで成功。近距離の線路部分は模擬ポートであり、実無線ではない。
- `cloud-relay.browser.mjs`：上記と同じ架空グループへ独立PWA Cが画面から参加。共有ボタン0回でAの回答・通報を取得し、元ID・作者・件数の一致、無事の一覧表示、元通報の詳細表示を確認。Cによる回答の作り直しや重複はない。
- 最後の依存順修正を含む1.5.23の再試験で作成した別の架空グループでも、同じPWA Cの受信・画面表示を再確認。最終結果も4項目成功・画面エラー0・共有ボタン0回。
- `CloudRecoveryTest`：架空Aの秘密鍵を削除して不在を再現した後、Bが保存したAの無事プロフィールを、実際のWorkManager経由で公開HTTPSへ自動送信。Activity起動・共有ボタン操作なしで成功し、選択中の別グループは変わらない。この試験はプロフィールのバックグラウンド経路を確認し、上記の安否回答・通報の試験とは分ける。
- `RelayAudienceTest`：本番の署名交換処理を20個使用。各端末のSOS回答と通報を全端末へ届け、2群に分断して各自を無事へ変更、交換処理を再作成して再接続。全20端末が元作成者の全60記録を保持し、繰り返し交換でも保存通知が重複しないことを確認。模擬通信路・メモリ保存の試験であり、無線速度やSQLite性能の測定ではない。
- `LocalSituationStorageTest`／`CloudStorageTest`／`RelayStorageTest`：旧版の保存内容を保持したRoom移行、署名の保存・再読込、改変拒否をエミュレーターで確認。
- 順番が前後する成立・回答・訂正と、根拠が後から届く場合の再試行について4件の失敗を確認して修正。恒久的な403／競合は停止し、進捗がない同期内ループは終了する。修正後のJVM全246件が成功。
- サーバー全40件、PWA単体全161件が成功。Android1.5.23/code36の通常版・試験APKのビルド成功。最終APKで端末内9件を再実行し全件成功（失敗・スキップなし）。通常版APKのSHA256は`e6ebee29179d50df3879cef9dc4298c44caa856de125ae8d77bb804963b63f6e`。
- この作業ではXiaomi／vivoの新しい2台無線試験や実機更新は行っていない。ユーザー不在で端末操作・承認を要求しない。
