# 地震時の衝撃検知・表示の設計案

作成日：2026-10-25。状態：計画レビュー用。実装・実機試験はこの作業では実施していない。

## 確定した目的と条件

- 位置記録が有効な間、端末への大きな衝撃を観測する。消灯・ロック中の観測は必須で、後回しの追加機能ではない。
- 速報の場合は端末が速報を受信した時刻、住民報告の場合は最初の報告時刻を基準Tとし、その1分前から10分後に起きた衝撃を「衝撃あり」として表示する。それ以外は最終的に破棄する。2026-10-25の利用者回答で確定。地震そのものの発生時刻は基準にしない。
- 同じ地震に速報と住民報告の両方がある場合は、両方の窓の和集合を採用する。どちらか一方の範囲に入れば対象。2026-10-25の追加回答で確定。
- 同じ地震の速報続報も、各続報の端末受信時刻の1分前〜10分後を対象に追加する。未採用の衝撃候補は直近24時間分を保持し、それより古いものを破棄する。いずれも同日の追加回答で確定。
- 採用した加速度の衝撃記録も直近24時間のみ保持する。既存vivo落下通知の30日保存とは別の仕様。
- 取り消された速報の時間窓だけに一致する衝撃は表示から外す。住民報告または別の有効な速報の窓にも一致するものは表示を維持する。同日の追加回答で確定。
- 複数回の衝撃は既存の詳細欄に最新日時を表示し、各回の記録は24時間保持する。同日の追加回答で確定。
- 表示は物理的な原因の証明や倒壊・SOSの自動判定ではなく、この時間条件に基づくアプリ上の扱い。
- Googleマップとの同等消費は採用条件ではない。著しい追加消費がなければ許容し、結果を見て利用者が判断する。
- 既存の位置記録、vivo落下記録、地震の手動報告・成立・終了、安否・救助のルールを勝手に変えない。
- plan.txt、旧Android Studioコピー、既存データは変更しない。新たな端末試験は操作と所要時間を事前に説明する。

## 現状と不足

`motion/AndroidMotionSource.kt`は加速度を取得でき、試験用100Hz＋部分WakeLockで受信を確認済み。ただし直近試験は途中に1回の画面点灯を含み、全区間消灯の成功とは扱わない。通常版の衝撃検知器はない。深いDoze、メーカー省電力、長時間運用は別途検証が必要で、電力差の過去3試験は未判定のまま残す。

`location/PositionService.kt`は位置記録・落下記録の所有者であり、通常版加速度はdebug校正指定時だけ動く。位置記録の停止・グループ変更・サービス終了への連携と既存復帰処理を再利用する。

`ui/SituationMap.kt`には個別アイコン右上の衝撃マーク、`ui/SituationScreen.kt`には人の詳細の衝撃日時がある。`MapPerson.impactAt`へ実データを供給する経路が不足している。広域集計には衝撃マークを追加しない。

時刻の接続先：住民報告は`core/QuakeLifecycle.kt`の`firstReportedAt`、速報は端末の受信記録の`receivedAt`を使用する。`eew/P2pWarning.kt`の`issuedAt`は速報の発表時刻であり受信時刻の代わりにしない。物理的な地震発生時刻の抽出はこの機能の前提から外す。アプリ内災害IDへの関連付けは別途必要。

既存FCM受信は別途実装されているが、2026-10-25の受信計画には上流WebSocketの429問題が残る。今回の計画だけで本番地震情報の受信が完成済みとは扱わない。地震情報の模擬入力による統合試験と本番受信の試験を分ける。

## 観測方式の比較と提案

| 方式 | 判定 |
|---|---|
| vivo落下通知だけ | 落下しない衝撃の捕捉と判定基準が不明。今回の主入力にはできない。既存機能として保持 |
| wake-up加速度計＋端末内バッファ | 対応機種では候補。機種の実能力・配信遅延・欠落を確認して採用。現在のvivoで使用可能とは確認できていない |
| 通常加速度計＋Foreground Service＋部分WakeLock | このvivoの実装候補。位置記録に連携し、Doze除外・vivoバックグラウンド設定を含めて成立を確認する。追加電力は未判定 |

推奨は既存加速度取得を主入力にした3番目をまず成立させること。wake-up経路が実際に使える場合は同じ検知器へ接続できる。100Hzは既存の試験設定として再利用する初期候補であり、製品に必要な最低頻度とは未確定。検知するパルスの幅と許容誤検知を決め、実波形で取りこぼしを調べてから下げる。低頻度で開始して動きを検知後に高速化する方式は、最初の衝撃を失うため初期方式にしない。

### 消灯中観測の必須条件

1. 位置記録を有効にした時点から監視を開始。地震通知が届くまで待つ設計にはしない。基準Tの10分後を過ぎても、位置記録が有効な限り次の地震に備えて観測する。
2. 通常加速度計では、監視の所有者が部分WakeLockを持ち、停止・終了時に解放する。位置の更新間隔を衝撃検知の周期に流用しない。
3. DozeではWakeLockも無視される場合がある。非wake-up経路では電池最適化除外の実状態を確認し、必要なら利用者が設定する導線を設ける。vivoの自動起動・背景使用設定も実機確認する。shellで設定した状態だけで通常利用可能と判定しない。
4. Android 14以降のFGS種別は、位置に加えて継続衝撃観測の用途を正しく宣言する。案は既存サービスに`location|specialUse`を付与し用途を明記。健康用途ではないため、検索結果に出た`health`を機械的に使わない。公開時の審査適合は別に確認する。
5. サンプル時刻と受信時刻を分け、遅延・欠測を検証する。必要なサンプルが来ない状態を「衝撃なし」と扱わない。最小限の監視状態を位置記録画面・既存通知に出す案とする。
6. 電源断・明示的な強制停止などOSがアプリを動かさない状態でも絶対に観測できるという保証はしない。通常の消灯・ロック・背景・Dozeは完成試験の対象から外さない。復帰可能な停止は既存復帰処理で再開し、観測できなかった区間を残す。

## 検知・保存・照合

```
位置記録ON
  → 消灯中も加速度取得 → 衝撃候補の抽出 → 端末内に一時保存
速報を受信／住民報告を取得
  → 基準時刻Tと対象災害を確定 → T−60秒〜T＋600秒に一致
  → 衝撃観測として保存・既存共有へ接続 → 個別アイコン／詳細日時を更新
位置記録OFF → 受信解除・WakeLock解放
```

時間条件は端点を含む案：`T - 60_000 <= observedAt && observedAt <= T + 600_000`。Tは速報受信時刻または最初の報告時刻。比較する衝撃側は実際の観測時刻を使い、センサー通知の配信時刻・画面を開いた時刻で代用しない。センサーの経過時刻をセッション開始時の実時刻へ変換する既存方式を再利用し、時刻補正・再起動をまたぐ換算を混ぜない。速報が遅れて届いた場合は、その遅れて届いた時刻をTとする。端末ごとの受信時刻を、共有先の受信時刻に置き換えて再判定しない。

加速度の候補は三軸の合成値、ピーク、幅を基本とする。重力込みか除去後かを検知方式の版とともに明示し、単発ピークを無根拠に棄却する連続回数条件は入れない。自由落下や回転は必須にしない。センサー範囲を超える入力は正確な強度へ換算しない。閾値・パルス幅・連続通知のまとめ方は未確定であり、実装者の判断だけで本番値を決めない。

常時の全波形をディスクへ書き続けない。検知に必要な短い波形をメモリで扱い、抽出した候補を永続保存する。速報受信時には直前1分を参照する。最初の住民報告が他端末から遅れて届く場合に備え、候補は直近24時間を保持する。採用済みの衝撃も観測時刻から24時間で期限切れとする。期限外の観測を遅延共有で受け取っても表示へ復活させない。

関連付け後は観測ID・端末/人物ID・グループ・災害ID・観測時刻・測定値・検知方法と版を保持する。端末位置は最新の既存位置と取得時刻を付け、衝撃の瞬間にGPS成功を待たない。位置不明でも衝撃を捨てない。端末位置を衝撃時点の正確な位置と偽らない。

遅れてより早い住民報告が届き最初の報告時刻が変わった場合は再照合する。速報内の発生時刻・発表時刻の訂正だけでは受信時刻を変更しない。新しい続報の受信ではその前1分〜後10分を追加する。同一メッセージの再配信は新たな続報とは扱わない。取消で無効になった関連付けは表示・共有先にも反映する。候補は他の地震窓にも入る可能性があるため、一件照合しただけで破棄しない。速報と住民報告の窓は和集合。異なる地震の窓が重なる場合とアプリ内災害への紐付け方法は仕様確認対象。訓練と実地震を混ぜず、衝撃で安否状態・災害成立を自動変更しない。

## 表示方針（Product Design）

既存の画面と素材を使う。拡大地図の個人アイコン右上に既存の中抜き衝撃SVG、人の詳細には既存の「衝撃」と日時を使う。新たなダッシュボード、強度の色分け、倒壊・危険度ラベルは追加しない。選択した災害に一致する観測のみ表示する。複数回は最新日時を既存欄へ反映し、各回の記録は24時間保持する（利用者回答済み）。未観測・監視停止を「衝撃なし」と表示しない。

案内が必要な監視停止・設定不足だけを位置記録画面と既存常駐通知で簡潔に伝える。消灯中に画面を勝手に点けたり全画面を開いたりすることは、この要件に含めない。再表示時に保存済み結果を即反映する。

実装で画面を更新した際は同じ作業でdemo/と公開サイトへ反映する。従来の比較画面を残し、右側に更新版を追加。上に版と追加・変更点1〜2文を表示し、画面案とAndroid実装版を区別する。架空データで表示・操作と公開反映を確認する。今回の計画作成では画面は変更しない。

## 実装前に確定が必要な判断

| 判断 | 計画案／状況 | 止める箇所 |
|---|---|---|
| 対象災害との対応 | 該当災害未確定なら表示保留を提案。速報と住民報告をどの災害へ関連付けるか確認する | 本番関連付け |
| 衝撃判定値・合格目標 | 日常動作と衝撃波形で根拠を作り、許容する誤検知・取りこぼしを確認して設定 | 通常版で検知を有効化 |
| 異なる地震との対応 | 既存の「管理者終了まで同じ報告期間」の仕様と速報のイベントIDを対応させる。複数衝撃の最新日時表示は確定済み | 災害への関連付け |

上記を隠して「このまま実装可能」とは扱わない。消灯中受信の基盤、時間窓の純粋ロジック、模擬データで表示接続する実装順は先に計画できる。

## 完了条件

- 対象端末でUSBなし・非充電・消灯・ロック・アプリ非表示のまま、深い省電力を含めて必要な加速度データが届く。単なる登録成功は合格ではない。
- 時間窓の境界、速報受信直前の衝撃、遅れて届く最初の住民報告、取消、対象外破棄を自動試験で確認。
- 検知→保存→災害との関連付け→選択災害の個人マーク／日時表示を一続きで検証。模擬入力と実測の結果を区別。
- 試験入力の画面反映だけで物理的な衝撃検出精度を確認済みとしない。安全な検証で合意した検知性能を満たす。
- 共有記録は既存仕様どおり交換・重複排除し、未照合の候補と連続波形は共有しない。
- 位置停止時に加速度・WakeLockが止まり、再開で受信が戻る。履歴は許可した保持ルールまで残る。
- 本番地震入力が未復旧なら「入力連携未完了」、消灯観測未成立なら「必須要件未達」と報告する。電力比較の失敗で他の完了結果を消さない。
