# Apple・Google監査の修正

対象は監査で確認した6点。Web1.6.17の4タブ構成を維持し、入力保護、更新、用語、文字拡大、押下領域、明暗テーマを修正する。

設計：既存のNoto Sans JP／OS書体、左揃え、見出し23–25・本文16・補助13を維持。明色は背景#FFFFFF、文字#183447、補助#536478、操作#155EEF、線#D6E0E8。暗色は背景#10212B、面#142630、文字#E4EFF7、補助#BDCDD8、操作#AAC7FF、線#617786。意味のある安否色と地図の危険度の色は独立して維持する。

```
4タブ → 案件 → 編集（下書きを保持）→ 保存
メニュー → 自分の情報・住居（名前と住居に集中）
           災害・訓練（地震の発生を報告／訓練を開始）
更新あり → 入力内容を保護 → 利用者の操作で再読み込み
```

自己レビュー：新しい装飾やタブ追加は不要。内部IDを消し、ラベルを動作に合わせる。英語のタブはPeople／Tasks／Safetyへ短縮する。テーマ変更は背景だけでなく補助文字、入力枠、選択状態、シートまで確認する。押下領域は48を基準とする。

確認：AndroidとPWAのタブ移動・閉じる・入力保持・明暗表示・文字拡大を検証。PWAは旧キャッシュからの移行とオフライン起動を再現する。公開PWAと比較ページへ反映し、既存の比較列を残す。実機読み上げなど未実施項目を全体準拠と誤記しない。

## 実装結果

- Android 1.5.37/code50、PWA 1.6.11。4タブ構成、災害開始条件、安否色、津波レイヤーとカメラ動作、通信・保存の権限を維持。
- 対応編集を案件・編集種別ごとの下書きとして保持。タブ移動・閉じるで失わず、成功した保存後だけ破棄。共有済み記録が変わった場合の確認は維持。PWAは同じタブの再読み込みにも対応するsessionStorageを使用し、ブラウザーを完全終了した後まで未保存内容を永続保証する仕様ではない。
- PWAの更新を検出して更新操作を案内。静的フォームの未保存入力や保存中は再読み込みを抑止。新しいキャッシュの準備だけで開いている文書を強制再読み込みしない。既存の記録・所属は消さない。
- Androidのプロフィールから内部グループID入力を撤去。現在の所属グループへプロフィールを保存。「地震の発生を報告」と操作を明示。変更ボタンの読み上げ名にも対象項目を付与。
- 英語タブをMap / People / Tasks / Safetyに統一。文字拡大時のAndroid集計・対応フィルターも列数を減らす。
- OSの明暗設定へ追従。背景、入力、メニュー、文字、選択状態をテーマ化。地図タイル自体の配色と危険度の色は独立。最終入力枠色は明色#7B8B98、暗色#8FA4B2に調整した。
- 凡例や閉じる操作の領域を48基準へ調整。PWAではCSS px、Androidではdpとして検証し、単位を同一視しない。

- Androidのローカル単体テスト：56スイート・248テスト成功。実アプリの独立した架空グループで下書き保持・プロフィール所属維持の2テスト成功。既存のグループ選択を復元。
- vivoを1.5.37/code50へ更新し、主要12画面を観察。メニュー8項目の遷移と閉じる・戻るを確認。OSは利用者の暗色設定を維持し、登録情報を変更しない。
- エミュレーターで明暗両テーマの4タブ・メニュー・プロフィールを確認。英語・文字200%の4タブとメニューを撮影し、画像も確認。終了時に日本語・文字1.0・明色へ復元。
- PWA：入力のタブ移動、閉じる、再読み込み、保存後の下書き消去、明暗、凡例領域、320px幅・文字200%の英語、Escとフォーカス復帰の8項目成功。別の編集競合試験でも共有記録の無確認上書きなし。
- 実際に配信されていた1.6.10から1.6.11への移行、更新中の入力保護、オフライン再起動後の所属・名簿保持を専用ブラウザーで確認。その後、公開1.6.11を起点にした次回更新も成功。前者の証跡は`output/platform-quality/upgrade/from-1610.json`、後者は`upgrade-current/verification.json`。
- 代表的な文字・操作・入力枠の配色10組で所定のコントラスト比を確認。文字4.5:1以上、入力枠3:1以上。画面中の全画素や全地図記号の包括的な測定を意味しない。
- 公開PWAの8ファイルが修正版と一致。最終キャッシュ`r30-quality`、Cloudflare deployment `39debb9e58224365b375a4c5c9609171`。既存バックエンドモジュール、GROUPSの保存先を維持。初回インストール後に画面を閉じないまま次の更新を受けた場合の案内も追加試験で成功。
- 内蔵ブラウザーはタブ取得時に`browser.user is unavailable`となったため、以前から許可された専用Playwrightブラウザーを使用。普段使いのブラウザーや公開グループへの書込みは行っていない。

## 指針との対応と確認範囲

Apple HIGの読みやすさ、文字拡大、色だけに頼らない状態表示、予期しない入力消失の防止を参照。GoogleのCore app qualityの標準操作、状態保持、明暗テーマ、タッチ領域、コントラストを参照して上記を修正した。

- Apple HIG Accessibility: https://developer.apple.com/design/human-interface-guidelines/accessibility
- Apple Feedback: https://developer.apple.com/design/human-interface-guidelines/feedback
- Google Core app quality: https://developer.android.com/develop/adaptive-apps/quality-guidelines/core-app-quality

今回指摘した6点の修正と上記の試験を完了しても、Apple/Googleの正式認定や全規則への全面適合を宣言しない。iPhone実機でのVoiceOver/Dynamic Type、Android TalkBackの全読み上げ順、全権限状態・端末サイズ・横向きの網羅試験は未実施。専用ブラウザーのCSS文字200%はiPhone実機のDynamic Type試験とは区別する。
