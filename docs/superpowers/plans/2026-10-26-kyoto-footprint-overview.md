# 広域でも建物だけを着色する表示

利用者が「区画平均の全面着色」をやめ、建物の輪郭を縮尺に応じて簡略化する方式を選択したため実装する。全壊率のモデル・震度6.2・10%/40%の分類は変更しない。

## 実装

- ズーム8〜13を、集計セルから簡略化した建物外形へ置換。同じ被害曲線分類の輪郭を最大128ポリゴンずつ束ねるが、建物間の空間を埋めたり、地域平均に置き換えたりしない。
- 簡略化の許容幅は512pxタイル換算0.2px。元形状と交差させ、簡略化による中庭・道路へのはみ出しを防ぐ。MVT量子化に伴う微小な位置丸めは残る。
- 表示面積0.01px²未満の形状は省略。ズーム14以上では既存の全収録建物の詳細形状・属性に戻る。高リスクだけを優先して残す選別は行わない。
- 広域の地図タップはその地点へ拡大。巨大な広域形状をタップのたびに読み出さない。個別の数値・属性は詳細表示で確認する。
- 地域平均の式と表示を削除。出典・凡例・初期震度・既存の色は維持。
- 詳細タイルは再生成しない。直前の検証済み投影データを再利用する際は元ファイルのハッシュと建物ID/曲線分類の全件一致を再確認する。通常の全件生成スクリプトも新方式へ更新する。

## 検証

1. 原形状外に簡略形状が出ないこと、中庭と建物間の隙間を埋めないこと、分類の保持、微小形状が拡大時に戻ることをPythonで検証。
2. 全タイルのハッシュ、詳細タイルの513,815棟のID・分類一致を検査。広域タイルから集計値 `n` / `f12` が消え、輪郭と分類だけになることを確認。
3. Androidのビルド・単体テスト後、エミュレーターで表示と操作を確認し、vivoで初回表示・移動・広域表示・広域タップによる拡大を測定。
4. 広域スクリーンショットを目視確認し、前方式の四角い領域着色がないことを確認する。測定結果を追記する。

## データ・ビルド検証結果

- 形状テスト6件と建物関連JVMテスト8件が成功。Android本体・端末テストAPKのビルド成功。
- 全2,329タイルのハッシュ、全広域タイルのスキーマを検証。広域は `footprints` レイヤーと曲線分類 `p` のみで、集計セルの `n` / `f12` 等は存在しない。
- 詳細タイルの513,815棟について元ID・曲線分類の全件一致、欠落0を確認。`data/2026-10-26-kyoto-footprint-integrity.json` に保存。
- タイル本体164,567,482 bytes。APK 239,754,367 bytes。versionCode 23 / 1.5.10。
- 広域の生成件数は、タイル境界で重複した建物も含む延べ数。ズーム8: 7,113、9: 55,986、10: 378,832、11: 505,650、12: 515,450、13: 517,475。遠方の微小形状を省略するため、全収録件数そのものではない。
- エミュレーターは同じAPI37のAVDを再開。PCの負荷を抑えるため今回は4仮想CPU・SwiftShaderで実行する。前回のエミュレーター値との厳密な性能比較には使わず、実機の結果を重視する。

## 端末での確認結果

- エミュレーターの画面操作テスト1件成功（126.24秒）。建物の個別数値、震度変更、凡例、広域レイヤーを確認。ソフトウェア描画環境では初回26.919秒、広域7.669秒と遅く、この環境の速度を実機相当とは扱わない。
- vivo V2417A / Android API36へ1.5.10を更新し、端末テスト1件成功（52.844秒）。全収録範囲への移動と、広域をタップすると詳細表示へ戻る操作も成功。終了後は通常のMainActivityへ戻した。再起動は行っていない。
- 実機の最初の建物検出まで433ms、広域への切替から中央付近の輪郭検出まで303ms。これはテスト画面での最初の表示検出であり、アプリの完全なコールド起動や全タイル読込完了の時間ではない。

| 実機の地図移動 | 着色なし・中央値 / 95百分位 | 着色あり・中央値 / 95百分位 |
| --- | --- | --- |
| 詳細表示 | 17.03 / 26.12 ms | 17.31 / 21.40 ms（2巡目17.70 / 21.57 ms） |
| 広域表示（zoom 10.3） | 17.94 / 19.45 ms | 17.27 / 21.24 ms |

- 広域は同じ3回の1秒間移動を着色なし・ありで実行し、実移動時間は各1.020〜1.036秒。今回の端末・範囲では大きな描画遅延の増加は見られなかった。値はMapLibreの描画完了コールバック間隔で、厳密な画面提示FPSやGoogle Mapsとの比較ではない。着色なしを先に実行しており、キャッシュの影響もある。
- 測定時のプロセスメモリPSSは990,548 KiB（約967 MiB）。デバッグ版・端末テスト込みの値であり、低メモリ端末や長時間利用の検証は別途必要。
- 実機・エミュレーターの広域画像を確認。以前の四角い集計セルはなく、河川・山地・公園など建物のない部分を一括で塗っていない。密集した市街地では、縮小された個々の建物の色が連続して見える場合はある。
- 生データ: [実機](data/2026-10-26-kyoto-footprint-vivo.json)、[エミュレーター](data/2026-10-26-kyoto-footprint-emulator.json)。実機の画像は作業フォルダー内 `.implementation/footprint-vivo/extent.png` と `buildings.png` に保存。
- 広域の検出範囲を中央10%に限定しているため、以前の集計セル版との初回検出時間を厳密な前後比較には使わない。
