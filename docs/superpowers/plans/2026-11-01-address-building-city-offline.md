# 住所⇔建物と、市全域の保存地図

2026-11-01。利用者から未実装の住所⇔建物対応、市全域のダウンロードへの変更要求を受けた。これは実装方針と調査記録であり、製品への接続完了を意味しない。

## 着手時の現状と変更要求

- Android `OfflineMapRepository.download` は現在地または住居の周囲2km四方、表示ズーム14〜18を保存する。市境は使用していない。
- PWAのService Workerはアプリのファイルと津波固定結果を保存するが、外部配信の背景地図は保存していない。
- 建物の登録・住戸・HOME対応は実装済み。ただしPlaceEventには住所・PLATEAUデータ版・PLATEAU建物IDの対応情報がない。建物の名称と位置の登録だけを住所⇔建物機能の完成とは扱わない。
- 追加計画B1/B6にあった住所検索・PLATEAUとの対応は未実装。これまでの実装状況と計画の区別を維持する。

## 確定した仕様

利用者が「グループの活動地域として管理者が設定した市」を選択。管理者だけが設定し、参加者へ共有する。現在のグループに市の設定はないため、グループ名から推定したり、既存グループを勝手に京都市所属へ変更したりしない。市データは現在の実装対象である京都市・熱海市から整備する。

## 住所と建物の流れ

1. 自分の登録情報から住所を検索し、町名・地番等の候補を選ぶ。
2. 位置情報がある住所はその付近へ移動。町の代表点しかない場合は番地の位置として扱わず、地図で建物を選ぶ。
3. 建物輪郭と住所を確認して関連付ける。一住所複数棟・一棟複数住所を許し、最近傍だけで自動確定しない。
4. PLATEAUの版・建物ID、アプリ内建物ID、住所原文、検索用表記、出典、確認者と確認時刻を保存する。建物から確認済み住所、住所から関連建物を相互参照できるようにする。
5. 既存の住戸・HOME・住民一覧へ接続。訂正履歴・再起動・Android/PWA同期・オフライン中継・署名を壊さないよう、通信形式の互換性も実装／試験対象にする。

画面は既存の登録情報と建物選択に組み込み、新しい常設タブを増やさない。検索候補→地図で確認→保存の順とする。既存の文字・色・操作部品を使い、出典や計算の説明を地図上に常時追加しない。

## 市全域の保存

- 市町村境界を使い、市全域と交差する地図区画を保存する。政令市の1区やPLATEAU収録範囲を「市全域」としない。
- 背景地図、建物の輪郭・属性、住所検索データの保存状況を分けて管理する。全て利用可能になってから「圏外で利用可能」とする。
- 保存前の対象市・容量、進捗、一時停止・再開、容量不足を扱い、取得途中を保存完了にしない。既存の保存地図や登録記録は移行時に勝手に削除しない。
- Androidは既存MapLibreを拡張。PWAは現在のラスター画像を広域かつ最大ズームまで丸ごと取得すると枚数が多いため、同じベクトル地図を使う案を比較する。既存の津波・住民・通報の地図操作と描画を保つことが受入条件。
- 現在の配信元OpenFreeMapは1回3,000タイルまたは50MB、並列4件以下、固有User-Agentという取得条件を示す。超過時に小分けを使って制限を回避する設計にしない。上限内での実測を行い、超える場合は再配布可能な地域パッケージ等へ切り替える。外部サービスの契約や課金を勝手に増やさない。

### 地図

国土数値情報N03・2025年版の京都市11区を取得。市全域の外接範囲は経度135.559005551〜135.878441946、緯度34.874915559〜35.321238892。

OpenFreeMapの取得時点のベクトル地図は最大ネイティブズーム14。市境と交差するズーム8〜14の区画数は380（うち14が260）。外接長方形では555区画。これより細かい表示でも同じベクトルを拡大描画する構成を検証する。

ズーム14の外接範囲から均等に16区画を採り、合計1,635,953バイトを実測。これは標本であり市全域の容量ではない。文字・アイコン・スタイル・他ズーム分も別途必要。全市保存時間と全容量は未実測。

PWAで使う地理院ラスター画像を単純に同じ外接範囲で取得するとズーム18だけで92,734区画になるため、現在の2km方式を市境に広げるだけで両端末を完成としない。

## 実装・検証結果（2026-11-01）

Android 1.5.41 / PWA 1.6.15。管理者がグループの活動地域を設定し、同じグループのAndroid/PWAが取得する。対応する市パッケージは京都市・熱海市。全国の市を選択できる状態とは区別する。既存グループには市を自動設定しない。

- 住所検索→地図で建物を確認→住所と建物の対応を保存。京都市ではPLATEAU輪郭を使い、含まれる棟を選択する。最近傍を自動採用しない。熱海市の住所検索・市全域の背景地図は対応するが、PLATEAU輪郭の対応付けは未収録で手動位置指定になる。
- 建物から確認済み住所を表示し、住所・名称による一覧絞り込み、訂正履歴、Android/PWA共有、中継形式を接続。保存する追加項目は住所・PLATEAU建物ID・データ版。確認者・日時は既存の作成者・イベント時刻、出典は版と配布索引に保持する。検索用正規化文字列は検索時に生成し、重複保存しない。
- Androidは国の市境に交差する全市のベクトル地図を保存する。京都の住所索引・建物データはアプリ収録済み。PWAは背景・住所・建物をまとめて保存し、途中再開・容量確認・破損チェック・圏外起動に対応。新しい常設タブは追加しない。
- 京都市の住所は座標がある94,336件、熱海市3,438件。町代表点と地番座標を区別。座標のない番地を町の代表点で代用していない。
- PWAの京都市保存は707リソース、約118.3MiB。Androidの地図保存は25,503,319 bytes／676リソース（同梱住所・建物を除く）。集計対象が違うので両者を同じ容量とは比較しない。
- Cloudflareから背景地図配信元への取得は403になったため、この方式は採用しない。検証済み公開データの同一スナップショットを既存GitHub Pagesへ配置。新しいサービス契約は不要。配信元URL・ハッシュ・地図／フォントの利用条件を配布データに残す。

### 確認したこと

- JavaScript 212件、Android JVM250件が成功。旧記録のバイト列、署名・中継、新形式を扱えない端末への明示的な更新要求も検証。
- エミュレーターで市全域の保存・中断再開・保存状態の復元・住所検索・ネットワークを無効にした地図描画が成功。
- vivoへ1.5.41を更新。地図保存試験成功（この実行で11.6秒、既存キャッシュを含む可能性があり初回速度保証ではない）。地図ライブラリの通信を禁止し、市の北・南・東・西と中心部の5地点で描画成功。端末全体の通信設定や既存の登録情報・安否記録は変更していない。
- vivoの自動画面起動はInstrumentation.startActivitySync内で停止したため、通常の外部起動に切り替えた。最終の描画試験1件は28.1秒で成功。アプリの描画処理の停止とは区別する。
- 公開PWAで2ブラウザーの地域設定・変更同期、住所検索・建物保存・別参加者への共有、市全域保存の中断再開、通信遮断後の再読み込み、実PLATEAU建物の選択、市内5地点の地図表示を確認。iPhone実機でのこの版の全市保存は未検証。
- 地域設定のみの変更も次の自動同期で取得し、保存中の地域変更は終了／一時停止後に表示を更新する。
- サーバーでJSON項目順が整列されると住所付き建物を内容衝突と誤判定する不具合を再現し、項目順によらない内容比較へ修正。差のある住所を拒否する動作は維持。
- 公開PWA最終 deployment `99ff80cc7edd4506b0bd81a08fb83690`、Service Worker `r37-city`。既存のGROUPS保存領域を維持。
