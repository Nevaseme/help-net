# vivo管理者と公開PWA参加の実操作検証

対象：Android 1.5.45で初回実操作、1.5.46/code59で更新後の共有確認。公開PWA 1.6.20。2026-11-02実施。

## 結果

vivoの通常UIで検証用グループ Team-1102-6F27 を新規作成し、京都の架空位置でデモ開始。独立したChromeブラウザーコンテキスト2つが公開PWAに新規参加した。APIで参加を代行せず、グループ名・パスワード→名前→安否の画面を操作した。

| 確認 | 結果 |
| --- | --- |
| 開始前のグループ名・パスワード参加 | 拒否される。待機室に参加できるとは案内しない。 |
| vivoの作成・管理者による開始 | 成功。ただし作成直後の遷移不具合を発見し、下記修正を実施。 |
| PWA確認A／Bの参加とSAFE／SOS回答 | 成功。住居登録なしで回答可能。 |
| PWAの京都地図 | 管理者を含む3人のマーカーを表示。 |
| vivoの一覧 | 初回は全員3人、無事2人、SOS1人。各参加者名・状態を確認。 |
| vivoからの回答の自動共有 | PWAに管理者AndroidのSAFEが届いた。 |
| PWAの圏外回答と復帰 | Aを圏外にし再読み込み、SOSへ変更、通信を戻すとBへ自動共有。修正版vivoでもAのSOSが届き、無事1人・SOS2人を確認。 |
| 作成・再開始・参加のAndroid回帰試験 | エミュレーター3件成功（54.273秒）。 |
| vivoへの修正版更新 | 1.5.46/code59のインストール成功。起動・一覧・グループ画面を実機確認。 |

圏外試験の初回は、自動試験が再読み込み直後の起動処理完了前に安否タブを操作し、起動時の地図遷移と競合して失敗した。再実行では圏外回答→通信復帰→別ブラウザー受信まで成功した。初回失敗を製品の修正成功としては扱わない。最終ブラウザーのページ実行エラーは0件。

## 発見した不具合と修正

旧グループの未回答デモを開いている状態で新しいグループを作ると、新グループの読み込みより先に旧グループの災害状態が参照され、管理者が安否の待機画面へ移動した。「作成してデモを準備」と実際の到達画面が一致していなかった。

`PlanApp.kt` の初回回答判定で、災害状態のgroupIdと現在のグループが一致することを確認する。グループ一致後の状態更新も画面遷移の監視対象に加えた。旧グループの未回答状態を使った `creationFromUnansweredDemoStaysOnGroupPreparation` は修正前に失敗、修正後に成功。推測上の競合ではなく実操作で発生した不具合への修正。
