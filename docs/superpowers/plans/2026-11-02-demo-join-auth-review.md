# 会場デモの参加方式・認証レビュー

追記：このレビューは1.6.19時点の記録。会場デモ向けの復元・停止・期限・参加終了制御と画面刷新は、[1.6.20実装記録](2026-11-02-demo-access-implementation.md)を参照。住居情報の配信範囲と厳密な同一人物判定は変更していない。

確認日：2026-11-02（日本時間）。対象はPWA1.6.19、共有Worker、Androidの既存の認証保存・API呼び出し実装。外部認証サービスの追加や有料プランへの変更は行っていない。

## 判断

今回のAPKインストールを挟む会場デモは、既存のAndroidとPWAで使える「グループ名＋共通の参加パスワード」を基本にする。名前はその後に登録し、会場の安否回答、地図へ進む。長い招待コードを観客に別途入力させない。既存の招待コード方式は通常のグループとの互換性のため補助操作として残す。

**これはグループへの入場許可であり、実名の本人確認ではない。** グループ名は秘密ではなく、名前とパスワードの2欄も多要素認証ではない。公開された同じ秘密を知る人を受け入れる方式なので、スライドの閲覧者・転送先を個人単位で区別できない。別端末・別ブラウザーでの重複参加を人物単位で防ぐ仕組みでもない。

| 方式 | 会場での使いやすさ | 安全性上の性質 | 今回の扱い |
|---|---|---|---|
| グループ名＋共通参加パスワード | Android/PWAに同じ説明を使える。2欄の入力 | 知っている人に参加を許可。表示名の本人性は保証しない | 基本方式 |
| 長い招待コード | コピー元が別端末・スライドだと入力しにくい | 現状は乱数256bit・24時間有効。共有すれば所持者が参加可能 | 補助操作のみ |
| 招待リンクのQR | PWAは入力を減らせる | QRは秘密の運び方であり本人確認の強化ではない | QR作成の段階で検討。現在のAPKにはインストール前の参加先を引き継ぐ処理がない |
| 個人アカウント／パスキー | 初回登録・復旧の説明が必要 | 個別の認証資格を使える。ただしパスキーだけで実名を証明するわけではない | 本番の管理者認証・住民運用で検討 |

## 公式資料との照合

本アプリにすべての規範が直接適用される、または準拠認定を得たという意味ではない。行政サービス向け基準やOAuth向け資料の概念は、対象と前提を区別して参照した。

| 参照元 | 適用した観点 | このアプリの評価 |
|---|---|---|
| [Apple HIG: Managing accounts](https://developer.apple.com/design/human-interface-guidelines/managing-accounts)、[Text fields](https://developer.apple.com/design/human-interface-guidelines/text-fields) | 不要なアカウント作成を課さない。入力の意味を明示し、秘密の入力を隠す。個人認証にはパスキー等を検討 | 参加者に個人アカウント作成を要求せず、グループ名と参加パスワードを明示。会場参加と個人ログインを同一視しない |
| [Google: Android Security checklist](https://developer.android.com/privacy-and-security/security-tips) | 資格情報の要求を最小化し、HTTPS、適切な端末内保管、短命なトークンと権限制限を考慮 | HTTPSとグループ単位の端末資格はある。短命化・更新・失効と、Keystoreを用いた資格情報の保護は不足 |
| [NIST SP800-63B-4: Authenticators](https://pages.nist.gov/800-63-4/sp800-63b/authenticators/) | パスワードの安全なハッシュ保管、推測対策、弱い値の排除、貼り付け対応。個人の単一要素パスワードには15文字以上 | ソルト付きPBKDF2とIP制限、貼り付けはある。弱い値のブロックはない。共有の入場用秘密をNISTの個人認証と同等とは評価しない |
| [デジタル庁 DS-511](https://www.digital.go.jp/assets/contents/node/basic_page/field_ref_resources/e2a06143-ed29-4f1d-9c31-0f06fca67afc/12cb1a6c/20250930_resources_standard_guideline_identityverification_01.pdf) | 目的・リスク・利用者・使いやすさに応じた本人確認。身元確認と当人認証を区別 | 架空データの会場デモと、住所・居住情報を含む本番で必要な保証を分ける。デモに本人確認書類を要求する設計にはしない |
| [IPA: セッション管理](https://www.ipa.go.jp/security/vuln/websecurity/session-management.html) | 推測・盗用・固定化への対処、資格情報の有効期間に注意 | 乱数資格とサーバーのハッシュ保管、既存端末の資格置換拒否を確認。ただし盗まれた端末資格をサーバーで取り消す手段がない |
| [Microsoft: Authentication vs. authorization](https://learn.microsoft.com/en-us/entra/identity-platform/authentication-vs-authorization) | 認証と、許される操作の判定を分離 | 「管理者」という表示名・送信パラメーターで権限は得られない。管理者操作はサーバーで拒否できる。共有パスワードは表示名の身元を確認しない |

## 実装と実験で確認したこと

- 認証・共有関連68件成功。新たに、未認証の名簿取得拒否、グループ名／パスワード誤りの共通エラー、役割パラメーターの偽装拒否、管理者端末IDの乗っ取り拒否、会場終了後のパスワード参加拒否を確認した。
- 一般参加者は招待発行、市の設定、会場開始、災害終了の管理者権限を取得できない。別グループの資格でも閲覧できない。
- Worker互換ランタイムで、同一IPから40件の確認と40件の参加を並行実行し成功。永続ストレージの再起動後も再試行で別人が増えない。40台の実機・会場電波の試験ではない。
- 入場パスワードはPBKDF2-SHA256・乱数ソルト・100,000回でハッシュ化して保存し、公開名簿に含めない。これだけでオフライン辞書攻撃への十分性を認定したわけではない。
- 端末の認証用トークンと通常の招待コードは32バイトの乱数で、サーバーにはSHA-256ハッシュを保存。人が選ぶ低エントロピーなパスワードを単純SHA-256で保存しているわけではない。
- PWAは入場パスワードを再試行用IndexedDBに永続保存しない。トークンはIndexedDBで保管。Androidはアプリ専用SharedPreferencesで保管し、バックアップ・端末移行の対象外。どちらもアプリ内の秘密をハードウェア鍵で保護する実装とは異なる。
- 会場参加のIP制限は120リクエスト／分。通常招待参加は別の30リクエスト／分の制限を共有する。よって今回の40人会場の基本経路を長い招待コードに変更するのは、UIだけでは足りない。

## 再現した不足（未修正）

以下はローカルの架空データで確認。公開サービスへの総当たりや他人のデータへのアクセスは行っていない。

| 項目 | 再現・根拠 | 影響／必要な対応 |
|---|---|---|
| 弱い共通パスワード | `12345678`を設定できた | ランダムな参加用秘密の発行、弱い入力の拒否などが必要。8文字という長さだけで安全とはしない |
| 端末資格の失効・更新 | 時刻を366日進めても参加済み端末の資格を受理。個別失効APIなし | 漏えいや端末紛失に対応できない。期限・更新・管理者による端末失効を設計する。圏外の未送信記録を消さないことが必要 |
| 会場終了と参加受付は別 | 会場終了後に、まだ有効な通常招待コードで新しいメンバーが参加できた | 会場終了はパスワード経路を止めるだけ。全参加経路の受付停止を別途整備する。既存参加者の通信まで勝手に止めない |
| 表示制御と情報保護は別 | 参加直後のメンバーが同期APIから他メンバーの登録住居データを取得できた | 「3分間名前を隠す」等は画面上の制御。サーバー側で配信制限する仕組みではない。実情報を扱うなら取得可能な情報を明示し、必要な認可を実装する |
| 端末での秘密保管 | PWAは同一オリジンJSから読めるIndexedDB、Androidは専用領域のSharedPreferences | 端末侵害やXSSで資格を盗まれた場合の回復策が必要。CSPや入力エスケープはあるが、漏えい後の失効を代替しない |
| 個人単位の同定 | 同じ表示名・複数端末で別メンバーになれる | 会場デモには利用できるが、実際の住民本人との対応を証明しない |

このため、今回の形式を使う場合も**会場専用のグループと架空位置・架空の住居データ**を使う判断であり、本番認証の準拠完了・安全性保証という結論ではない。失効はインターネット未接続端末へ即時配信できず、一度渡った情報を未接続端末から即座に消去できるわけでもない。
