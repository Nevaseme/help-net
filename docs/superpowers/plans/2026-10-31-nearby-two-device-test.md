# Android 2台・インターネットなし通信試験

## 着手時の確認

- 利用者が2台目を接続したため、実無線の試験を開始。
- Windowsはvivo（iQOO Z9 Turbo+）とXiaomi 11Tを認識。
- ADBはvivoとエミュレーターのみを認識。Xiaomi 11TのUSBデバッグ接続は未成立で、利用者にロック解除と許可を依頼中。
- vivoの通常版は1.5.20 / versionCode 33。まだ無線設定や保存データは変更していない。

## 実施予定と判定

1. 2台のアプリ版・権限・所属グループを確認。既存記録を消さず、試験記録を識別する。
2. 試験前の無線設定を記録。携帯回線と外部インターネットへの接続を止め、近距離通信に必要なWi-Fi・Bluetoothは有効にする。インターネットの利用可能性と既定経路も確認する。
3. 通常アプリの「近くの端末と共有」で発見し、双方の接続コード一致を確認して接続する。
4. 双方向に識別可能な記録を交換し、相手側の保存内容と送信側の受領確認を照合する。接続表示だけを成功としない。
5. 接続済みの受信側を消灯して別の記録を送り、保存・再表示を確認する。
6. 切断中に更新し、前面で再接続した後の再送と重複を確認する。
7. 結果を保存し、試験で変えた無線設定を元へ戻す。

最初の目安は準備後15〜20分。計画書にある前面30分・消灯30分・通常/省電力・3台中継の全試験とは区別する。

## 実装から分かった範囲

NearbyTransportはP2P_CLUSTERを使用。SyncEngineは同一groupIdの記録のみを扱い、保存後に受領確認を返す。SharingSessionは接続済み相手との背景共有を維持するが、前面を離れると新規探索を止め、接続相手がいなくなると共有を停止する。したがって現状は、計画にある背景での自動探索・自動再接続まで実装済みという意味ではない。

## 結果

2026-10-31、vivoとXiaomi 11Tの通常版1.5.20 / code33で実施済み。携帯回線を停止し、Wi-Fiは無線を有効にしたまま外部ネットワークから切断。両端末の既定ネットワークがない状態を確認した。

| 項目 | 実測結果 |
|---|---|
| 初回の双方向同期 | 相互に2人分の住民記録を保存 |
| Xiaomi消灯中の受信 | Dozing中にvivoの更新を保存 |
| vivo消灯中の受信 | Asleep中にXiaomiの更新を保存 |
| 切断中の更新 | 送信側に残り、受信側は旧版のまま |
| 手動再接続 | 保留した更新を配送、両端末の記録が一致 |
| 重複と既存データ | 試験グループは2人のまま。vivoの元のグループの住民記録は試験前と一致 |

実際の経路はBLEで相手を発見し、暗号化したBluetoothの接続で転送。Wi-Fi Directの転送成功を確認したものではない。証拠はGit管理外の `.implementation/nearby-20261031/verification.json`、各端末の保存内容・条件JSON・無線ログに保存。

終了時に無線設定を復元し、vivoを元の「iPhone確認」へ戻した。Xiaomiは試験グループを保持。USB接続・同室・短時間の住民記録転送に限る。実際の災害やSOSは開始していない。長時間、距離、深いDoze、自動再接続、3台中継、多人数、およびQRからの新規導入は未検証。

## 本番デモを想定した追加試験

利用者の目的は、聴衆がQRからAPKを取得し同一グループに参加した後、インターネットなしで相互の存在を確認できること。2026-10-31、利用可能な2台で追加試験に着手。

確認対象：通常画面でのグループ作成と招待参加、インターネット切断後の新しい更新の配送、接続拒否からの再試行、無線切断からの復帰、プロセス終了後の記録保持。保存済み住民一覧と現在接続中の相手は区別する。多人数・中継は2台では判定しない。

### 追加試験の結果（2026-10-31）

通常版1.5.20/code33のまま実施。利用者の外出に合わせて中断し、再開指示後に継続した。新しい架空グループ `Demo-1031` をXiaomiの通常画面から作成し、vivoを通常の招待入力・参加ボタンで加入させた。招待発行・コピー操作も確認。コードの端末間転記には試験補助を使用したため、QRからの導入成功とは扱わない。

| 項目 | 結果・証拠 |
|---|---|
| 同一グループへの参加 | 管理者1人・参加者1人、2台に2人分の記録 |
| 接続拒否→再要求 | 一度拒否して未接続へ戻り、再要求で一致したコードを承認して接続 |
| 圏外で新規更新を双方向転送 | vivoの `DEMO-A-03` とXiaomiの `DEMO-B-01` が相互保存。受信前・後のDBと両端末の既定ネットワークなしを照合 |
| Bluetooth切断中の更新 | Xiaomiの `DEMO-B-OFFLINE` は同端末だけに保存され、vivoは旧版のまま |
| Bluetoothオンだけでの復帰 | 復帰しない。オン後約50秒経ってもXiaomiは共有停止、vivoの記録は旧版 |
| 手動で共有開始・再接続 | 切断中の更新を受信し、2台の住民記録が一致。重複なし |
| プロセスを終了して圏外で再起動 | Xiaomiに所属・2人分の記録・最新更新が残り、一覧を表示できた |
| 一覧を「現在この場にいる人」として使う | 不適合。切断した相手も残り、訓練前は名前が「応答なし」になる |

新しい更新はインターネット遮断後に通常画面から保存。共有前のクラウド取得だけをNearby成功と誤認しないよう、送信側だけが新版の時点と受信後を比較した。USBは操作・記録採取用であり、同期の中継には使用していない。私的な証拠と照合コードは `.implementation/nearby-demo-20261031/` に保存し、Gitへ追加しない。`verification.json` の10項目は全成立。

### 発見した本番前の課題

1. **グループ変更後のプロフィール入力状態が古い。** 旧グループで「自分の情報」を開く→招待で別グループへ参加→再び「自分の情報」を開いて保存、で旧グループへ戻り、その記録を更新した。`PlanApp.kt` の `SaveableStateProvider(tab)` がグループを含まず、離れている間のグループ変更後に以前の入力状態を復元することが原因候補。`rememberSaveable(group)` だけでは保存済み状態の復元を防げていない。画面・保存先DB・選択グループを照合して再現を記録。製品コードは今回変更しておらず、**未修正**。
2. 上記の誤更新は元の1件を試験前の値へ戻した。復元補助の初回転送に不一致があったため、バックアップをバイト単位で照合して再転送し、全11件を保全。復元後の元グループの行が試験前と一致することを検証した。その後はアプリの再起動で入力状態をクリアして通信試験を続けた。この回避操作なしの一連の導入は合格としない。
3. **参加だけでは自動接続しない。** 各自の共有開始・相手選択・双方のコード照合が必要。無線復帰後も手動再接続が必要。計画の6Dにある自動接続・自動再接続は実装済みとは扱わない。
4. **登録名簿と現在の存在は別。** 一覧の2人表示は保持した記録。現在接続中の人数・名前は共有画面で別に確認する。位置更新時刻を現在の到達可能性と読み替えない。
5. **導入・配布。** GitHub Releasesは確認時点で0件。リポジトリ内の公開デモにもAPK配布・QR参加導線は見つからず、Android Manifestにも招待URL受け取りはない。外部で用意された配布URLの有無までは断定しない。QR→APK取得→新規インストールは今回未検証で、配布先と導線の整備が別途必要。
6. **権限案内。** Xiaomiではプロフィール登録・アプリ再起動時に位置権限を求める端末設定画面が開いた。本番手順には通知・近くのデバイス・位置関連の案内が必要。無線をオフにすると共有停止するため、「外部ネットは不要、Wi-Fi/Bluetooth無線はオン」を明示する。

この追加試験はUSB接続、2台、短時間、住民記録の検証。通常/省電力各30分、消灯30分、離脱復帰3回、未設定端末の初回導入、会場での距離・干渉、多人数、中継は未検証。最初の消灯受信試験と合算しても本番デモの全条件達成とはしない。

### 追加試験後の状態

- 共有は停止。vivoの選択グループを元の「iPhone確認」に戻し、画面でも確認。試験グループの所属・記録は保全。Xiaomiは `Demo-1031` を表示。
- 携帯回線・Wi-Fi無線・Bluetoothは試験前の値へ復元。vivoで一時停止した2つのWi-Fi自動接続もオンへ復元。
- **復元残件：Xiaomiの、試験開始時に使っていたWi-Fi接続先の自動接続。** 外出後その接続先が圏外になり、端末の保存済み一覧では削除操作しか確認できなかったため、オフのまま。ネットワークの資格情報は削除していない。接続先が見える場所で詳細画面を開き、自動接続をオンにする必要がある。ネットワーク名等は非公開の試験フォルダーにのみ記録。
- 最終DBでも2台の試験グループ記録は一致。元のvivoグループの住民行は試験前と一致。製品コード・デザイン・公開版・APKは変更していない。
