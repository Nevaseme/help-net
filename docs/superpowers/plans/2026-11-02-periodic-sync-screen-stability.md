# 定期同期による画面変動の修正 — Android 1.5.44

## 原因と修正

利用者が指摘したのはvivoのグループ画面。ただし他画面にも起きるため共通処理を修正。

- 15秒周期のCloudController.syncが、ユーザーの登録操作と共通のCloudState.busyを変更していた。グループのボタン・入力欄・訓練開始欄が無効化され、参加フォームには進捗欄が出入りしていた。同期のたびにCloudStateを購読する各画面も更新された。
- 通信中の状態を独立したStateFlowへ分離。「通信の詳細」だけがこれを購読する。一般画面へは同期開始の通知を流さず、実際に変化した結果・データだけを流す。
- 同期エラーと登録操作のエラーを分離。再試行の開始だけでエラー欄を消して再挿入しない。
- 同期中に押された登録・招待・活動地域・訓練の操作は、既存のMutexで直列に実行する。待機に入る前に操作を予約し、二重送信と取りこぼしを防ぐ。
- 住居選択などで使うResidentMapの注釈再生成を、AndroidViewの毎回のupdateからデータ依存のLaunchedEffectへ移動。無関係な再構成でマーカーを消して作り直さない。
- 自動同期の15秒周期、通信復帰処理、記録の取得・保存は継続。今回PWAのソースとWorkerは変更していない。

## 検証

- 修正前のCloudPollingStateTestは「Automatic sync must not set the group form's busy state」で失敗。修正後は実際のHTTPS同期成功、変更なしの次回同期で全体UI状態の発行0回、同期待機中の招待操作が完了することに成功。
- JVM単体251件成功。既存StatusFeedbackLayoutTestの2件成功。
- エミュレーター: グループ・自分の登録情報・訓練・アプリ設定・安否・一覧・地図・対応で、同期を実行しつつ表示要素の位置、文言、enabled、focusを比較。最終2件105.307秒成功。追加の操作待ち試験1件1.965秒成功。
- vivo: 同じ8画面の実操作試験1件72.841秒成功。グループは33秒間、自然発生の同期2回を含む244サンプルで表示不変。その他の7画面も各1回以上の同期中に表示不変。既存グループ・住居・訓練に保存操作なし。
- エミュレーターとvivoのグループ画面で、同期前後のアプリ領域（OSステータスバー等を除外）の画像差分は0ピクセル。
- 通常APK1.5.44/code57をvivoへ更新済み。
