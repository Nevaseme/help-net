# 消灯中加速度観測の実装記録

対象計画：2026-10-25-earthquake-impact-implementation.md。実装進行中。未検証を完了扱いにしない。

## 作業範囲と判断

- 利用者の指定順に、通常版の加速度観測→実機の消灯・省電力確認→衝撃判定・表示を進める。後段の未確定仕様は一つずつ質問する。
- 既存codex/android-demo-designブランチに多数の未コミット実装があり、それらを前提とする継続作業。既存変更を保持して同じ作業ディレクトリを使用し、一括コミットや別コピーへの同期をしない。
- 観測基盤の初期要求は既存と同じ100Hz。これを衝撃判定精度の合格値とはしない。1秒の無受信検知は監視停止の状態表示用であり、1秒の衝撃取りこぼしを許容する意味ではない。
- 波形全件の永続化や未承認の衝撃閾値は追加しない。実機試験には通常の観測処理と、追加のWakeLockを持たないdebug集計を使う。
- 速報・報告の併存は両窓の和集合とする回答を取得。続報・閾値・保存期間などの判断は後段に残す。

## 進捗

- 変更前実行はSDKパス未設定で停止。環境変数で既存SDKを指定して復旧。新規テストが未実装参照で失敗することを確認後、実装後の単体139件が成功（新規8件）。変更前全テスト成功とは記載しない。
- 試験記録の解析は4件の人工ログ試験で、受信停止・集計中断・Dozeの時刻不一致を区別することを確認。
- 新規監視の開始・受信・停止・無受信・設定不足・WakeLock解放のテストを先に作成。
- 接続端末V2417Aを確認。既存の電池最適化除外あり。まだ設定変更・実機試験を実施していない。
- 利用者から「指示するまでは実機を操作せずエミュレーター利用や設計を」と指定あり。実機更新・設定変更・試験を開始せず、エミュレーターと仕様確定を続ける。
- 初回エミュレーター試験はBIND APPLICATION ANRで起動失敗。再実行で9件中1件が失敗：wake-up試験入力に対して端末既定センサーの設定状態を参照して再登録していた。購読中センサーの能力を確認するよう修正し、再試験する。他8件は成功。
- 続報ごとの時間窓追加、未採用候補・採用衝撃の両方の24時間保持、取消速報だけに一致する衝撃の表示除外を確定。
- 複数衝撃は最新日時を表示し各回を24時間保持する回答を反映。plan.txtの「速報受信または住民報告で地図利用」と、既存決定の「管理者終了まで同じ報告期間」も読み直した。速報と報告のID対応は後段に必要で、既存仕様を未確定と取り違えない。
- 第三者の読み取りレビューで背景移行待ちの不足が指摘された。Activityの状態変更だけでなくProcessLifecycleOwnerの背景遷移を待ち、受信状態と件数を確認する試験へ補強。観測処理の所有権・解放に重大な指摘なし。実機性能が確認されたという意味ではない。
- 補強後の試験は起動が遅いとSTARTINGから無受信のINTERRUPTEDへ移っており、固定の瞬間状態を期待した試験が失敗した。登録だけではOBSERVINGにならず件数0、サンプル後にOBSERVINGになることを確認する試験へ修正。最終`impact-lifecycle-stable.log`は1件成功。既存MotionDeviceTest/DropDeviceTestは直前の再試験で8件成功（手動校正の未指定ケースはスキップ相当）。
- 更新直後のBIND APPLICATION ANRを保存して確認。スタックはAndroidJUnitRunnerのPlatformTestStorageRegistry初期化からServiceLoaderがAPKのZIP一覧を読んでいる箇所。観測処理のデッドロックを示すものではないが、初回起動タイムアウトは発生記録として残す。
- エミュレーター通常アプリで設定不足時のSETTINGS_REQUIRED・位置記録継続を確認後、試験用に電池最適化除外・疑似非充電・省電力・強制Dozeを設定。実機には同操作を行っていない。

## エミュレーターの消灯・省電力確認

2026-10-25、emulator-5554、Goldfish 3-axis Accelerometer（non-wake-up）、通常のPositionServiceを使用。試験ランナーやPowerComparisonServiceで観測を保持せず、mainの観測処理とその部分WakeLockを使用した。debug集計は5秒ごとに状態を読むだけで、自身のWakeLock・センサー購読・アラームはない。

| 条件／指標 | 結果 |
|---|---|
| 設定不足のまま位置記録 | 位置記録は継続、監視はSETTINGS_REQUIRED、観測件数0 |
| 試験用の最適化除外を追加 | 位置記録を再開し直さず観測開始 |
| 消灯・強制deep Doze・省電力が同時に有効な集計区間 | 121.699秒 |
| 同区間のサンプル増加 | 12,193件、約100.19Hz |
| センサー時刻の最大間隔 | 10ms |
| センサー時刻からコールバックまでの最大遅延（観測セッション全体） | 838.962ms |
| 集計の完了／停止・古いサンプル・集計中断の判定 | 完了記録あり、解析上の問題なし |
| FGS／CPU保持 | location＋specialUseを実行時にも確認、PlanD:impact-observationの保持を確認 |

これは仮想センサーと強制Dozeの結果であり、vivoの実センサー・自然なDoze移行・非充電の実消費・衝撃検知精度の証明ではない。遅延の最大値も記録し、「瞬時に反応できた」とは報告しない。OS状態は5秒ごとの観測であり、連続全時点の状態を証明するものではない。

試験後は強制Doze解除、省電力を元の0へ戻し、battery reset、追加した最適化除外を解除し、エミュレーターのPlanDを停止。PlanDのWakeLock解放・deviceIdle=false・元のAC給電状態を確認した。除外解除の初回はPowerShellの引数解釈で失敗したため引用符を付けて再実行し、Removedとリストからの消失を確認した。実機の更新・設定変更・再起動は行っていない。

証拠（Git管理外）：`.implementation/impact-emulator-doze.jsonl`、`impact-emulator-doze-analysis.json`、`impact-lifecycle-stable.log`、`impact-monitor-red.log`、`impact-observation-fix-build.log`。Android単体139件成功、解析用Python4件成功、エミュレーターの最終背景ライフサイクル1件成功と既存センサー8件成功を確認。lintDebugは0エラー・62警告（WakeLockの解放を別オブジェクトへ渡す箇所などを含む）。全項目を1回の試験で同時に確認したという意味ではない。
