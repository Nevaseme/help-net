# 会場デモの地図自動準備と虎ノ門データ

## 実装

- Android 1.5.52 / PWA 1.6.26。
- 開催中の会場デモが `KYOTO` なら京都市、`ACTUAL` なら東京都港区を地図保存・省略住所検索の対象にする。グループの通常の活動地域は変更しない。
- 管理者だけでなく、開催中のデモに参加した端末も自動準備する。京都の架空位置を選ぶために、活動地域を京都へ設定し直す操作は不要。
- 現在地モードの初期中心は虎ノ門ヒルズ（35.6665, 139.7495）。参加者の位置は引き続き実際に取得した座標を使う。
- Android は同梱の住所・建物資料と MapLibre の保存地図を利用。表示中に準備し、画面を再び開いたときや通信が復旧したときに未完了分を再開する。
- PWA は京都約219MB、港区実測18,266,154バイト・187ファイル。検証済みの全ファイルが揃った時点で保存完了とする。途中でモード変更した場合は旧地域の取得を中断し、新しい地域を用意する。保存途中のデータを完了扱いにしない。既存の港区保存に建物資料が含まれない場合は更新する。
- 初回はオンラインでアプリを開いて保存完了を待つ。iOSでアプリを閉じた後もダウンロードが続くことは保証しない。
- タブ配置・公開比較ページは変更していない。

## 虎ノ門周辺のデータ

地図・住所・施設名検索は既存の港区パッケージ（ABR、位置参照情報、OSM施設索引）を利用。虎ノ門ヒルズと「港区虎ノ門1丁目23番1号」の検索を確認。

建物の取得範囲は西139.7384、南35.6575、東139.7606、北35.6755の約2km四方。範囲に接する建物は輪郭全体を保持する。港区・千代田区・中央区の2025年度PLATEAU公開CityGML 14ファイルを照合し、重複4,653レコードを除いて5,033棟を収録。住所検索の対象地域は港区全域であり、隣接区の住所一式を追加したわけではない。

各公開ファイルのURL、取得日時・チェックサムは `toranomon-building-assessment/index.json` の inputs に保持。生成元は `tools/building_analysis/toranomon-sources.json`。形状を低ズーム用にも簡略化し、全域を一括展開せず必要なタイルだけ表示する。

| 属性・評価 | 棟数 |
|---|---:|
| 建築年あり | 0 |
| 構造種別あり | 0 |
| 地上階数あり | 3,984 |
| 被害関数による全壊率を計算可能 | 0 |
| 16階以上：既存の合意済み仮定による0% | 132 |
| 評価不明 | 4,901 |

建築年・構造を高さや所在地から補完していない。132棟は `assumed` と `cabinet-highrise-zero-assumption` を保持し、耐震診断結果にはしない。残る建物は形状を表示できるが、全壊率の数値は出せない。京都の数値や分布を虎ノ門へ流用していない。

## 検証

- Android の全単体試験261件を実行し成功。新規の地域選択、別地域が誤って対象にならないこと、5,033棟の読み出し・評価状態・重複排除の試験を含む。
- エミュレーターおよびvivo：京都・港区を自動保存し、保存状態を復元。MapLibreをオフライン状態にした後、同梱住所と虎ノ門建物を取得。各1試験成功。グループ・住居・参加者の記録は変更していない。
- PWA：京都保存中→現在地モード切替→港区自動保存→ブラウザーのネットワークをオフ→施設名・住所・建物検索。通常の活動地域（試験では熱海）が維持されることも確認。
- 公開PWAの同試験成功。圏外で背景地図と虎ノ門の建物510フィーチャーが描画されることを確認し、スクリーンショットを確認。
- 公開PWAのグループ作成→デモ開始→安否回答→地図の既存動線試験も成功。
- Android描画試験：エミュレーター571、vivo440フィーチャーを描画。縮小表示→再拡大でも建物レイヤーが戻ることと、スクリーンショットを確認。vivoは試験側のActivity起動待ちを避け、外部から通常起動して同じ描画検証を実行。
- 生CityGML全14ファイルに建築年・構造種別タグ自体がないことも再確認（検索ヒット各0件）。
- iPhone実機固有の今回の自動保存試験は未実施。以前の住所・位置の圏外再起動確認とは区別する。
