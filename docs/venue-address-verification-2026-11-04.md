# 会場デモの建物住所照合（2026-11-04）

新しく開始する御所南〜烏丸御池デモの割当を、町代表点からの「付近」表記から、公開住所を確認した12棟・64配置に変更した。12棟とも、住所資料に明記された建物名とOSMの建物名を対応させ、OSM建物形状とPLATEAU建物形状の面積重複を双方向で検証した。64配置は集合住宅内の架空参加者の位置であり、64棟・64実在住戸を確認したという意味ではない。実在の部屋番号・住人情報は使用しない。

## 確認の範囲

- 精度区分は `verified-building-address`。公開された番地付き建物住所と建物形状の対応であり、登記地図・筆界・所有権を確認したものではない。京都市全域の自動住所照合が完成したという意味でもない。
- 承認済み範囲は東経135.758〜135.767、北緯35.011〜35.018。範囲を拡大していない。
- OSM側・PLATEAU側の両方に対して面積重複率75%以上、該当PLATEAU建物が一意、レビュー済みIDと一致、配置点が両形状の内部という条件を必須とした。実績はOSM側77.0〜100%、PLATEAU側77.8〜98.9%。最寄り点や逆ジオコーディングは使っていない。
- OSMの `building=office` タグだけでは用途を確定しない。アスヴェル・グランドパルティール・THOUSEなどは公開の集合住宅資料でも確認した。サニーフォレストはOSMの集合住宅タグと複数の実在テナントの公式住所による複合用途の建物で、住戸構成までは確認していない。
- PLATEAU属性は元データのまま。12棟中、築年・階数・構造の全項目あり8棟、築年・階数あり／構造なし2棟、3項目なし2棟。住宅広告とPLATEAUの築年・階数に差がある場合も、広告でPLATEAU属性を置換しない。
- 元の64棟と今回の12棟は重複0棟。既存デモの設定スナップショット、登録済み住居、端末位置、署名済み記録はこの生成処理では変更しない。既存デモの「付近」住所が更新されたとは報告しない。

## 再生成と検査

Python 3とShapely 2が必要。今回の実行版はShapely 2.2.0。`python tools/building_analysis/build_venue_homes.py` で新規デモ用カタログを生成し、`--check` は書込みせず一致を検査する。入力の住所資料は人が確認した小さなリストであり、町代表点から自動的に住所を作る処理はない。

- `test_venue_addresses.py`：5件成功。64点の両形状内部、一意の12建物、元の属性保持、別棟ID・出典欠落・町付近・重複形状の拒否を検査。
- 会場サーバー単体試験：20件成功。住所と出典、64配置／12建物、40参加者の別々の配置を含む。
- 実Worker試験：40同時参加とSQLite再起動後の維持が成功。初回は実行環境のローカル通信制限で失敗したため、通信可能な環境で再実行し成功した。
- 建物詳細の回帰試験も成功。旧登録住居の固定IDを新規割当カタログから独立した試験用データとして保持し、旧住居IDによる照合と新しい12棟の実際の同梱属性の両方を検査した。
- 証跡の12件すべてで、OSM形状・名前・版がダウンロードした公開XMLと完全一致することを確認した。
- この作業では公開配布・既存デモの更新は実施していない。

統合後、PWA 1.6.35とともにカタログを公開した。新規デモの番地住所と建物属性を公開画面で確認。既存デモの変更は行っていない。公開配布の検証とAndroidへの反映状況は `decisions-correction-2026-11-04.md` の追加反映節を参照。
