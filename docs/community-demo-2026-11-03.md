# 会場デモ・地域集計の実装結果（2026-11-03）

## 使い方

1. 管理者のAndroidでグループを作り、グループ画面から「デモを開始する」を開く。参加パスワードと、京都の架空位置／参加者の現在地を選ぶ。
2. 新しく始めた会場デモには、12人の架空住民、3件の通報・資材要請、2人の救助済み履歴が入る。無事4人、応答なし4人、SOS2人、SOS後に救助済み2人。負傷あり2人、負傷なし4人、負傷情報不明6人。聴衆の参加枠は消費しない。
3. 聴衆はグループ名・参加パスワード→名前→安否回答→地図の順で参加する。京都モードでは聴衆・管理者にもPLATEAU建物の住居が割り当てられる。現在地モードの聴衆は実際の位置を使い、集計では「会場参加者」に分ける。実住居は書き換えない。
4. 「対応」→「地域集計」で、町内会別の人数、無事、SOS、救助済み、応答なし、負傷者、負傷状況不明、通報、不足資材を一つの画面で見る。
5. 「負傷情報」を開くと本人・住民ごとの負傷状況を記録できる。SOSや救助済みから負傷の有無を推測しない。記録は通常の共有経路で他端末へ送られる。
6. 「レポートを発行」で、その時点の集計を端末に保存。「発行済みレポート」からHTMLまたはJSONを取り出せる。HTMLはブラウザーで表示・印刷できる。発行済みの内容は後から変わらず、最新状況は再発行する。発行済みレポートファイル自体は端末ごとの保存であり、自動配布は行わない。
7. アプリ設定で日本語／Englishを選ぶ。架空住民の名前・メモ・部屋の説明・通報文・資材名はどちらの言語でも英語のまま。元データの住所は日本語の公的表記を保持する。

町内会は、実在の町内会境界を示すものではなく、デモ用に京都の建物群を3地区へ分けたもの。架空住民は「架空住民」と表示する。通常のグループではそのグループを一つの地域として集計する。

既に開始済みのデモ・訓練は勝手に作り直さない。新しい架空シナリオは、今回の更新後に新しく会場デモを開始すると作られる。既存記録を削除しない。チーム内の練習と本番は同じ手順で使える。

## 住所検索・画面整理

- 共通の正規化規則で検索用データを事前生成。特定の住所だけの特別処理は行っていない。
- vivoの検索処理：初回17,567ms→3,196ms。24回の通常検索は中央値51.12ms、95パーセンタイル80.83ms。初回は約82%短縮。これは候補検索の時間であり、地図描画・GPS取得は含まない。
- 住所選択画面は、検索・地図・選択住所・確定に整理。住所の編集は必要時だけ開き、キーボードで見出しが画面外に押し出される問題を修正。

- 集計を開いたままの他端末からの更新、および次の訓練に前回の通報・負傷を混ぜないことも確認。
