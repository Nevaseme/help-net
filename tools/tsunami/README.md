# 津波の条件比較用計算

地震の震度とは独立して、指定した海岸基準地点の最大水位上昇を目標値へ合わせる条件比較。利用者は0〜35m・1m刻みの36条件を事前計算して配布する方式を選択した。PWAとAndroidは同じ保存結果を読み、利用時にこの開発PCや計算サーバーを必要としない。ANUGA 3.3.10のオフラインアダプターは独立検証用に維持する。現在の公開状態は[STATUS](../../docs/STATUS.md)を参照し、生成用コードの存在だけでデータ配布済みとは扱わない。

## 保存結果の生成と表示

- `run_precompute_batch.mjs` は各整数高さを大小2領域で独立計算し、両結果と領域比較を保存する。全36条件の合格後に原本manifestを作る。不合格や途中の結果を完成セットとして配布しない。
- `build_precomputed.mjs <reviewed-pair.json> <source-manifest.json> <new-output.json>` は原本・地形・計算条件・校正・静水・質量収支・境界・領域差を再検査して地図用セットを生成する。既存出力を上書きしない。
- `lab/web/tsunami-precomputed.mjs` は同梱セットを検証し、指定した整数高さの実計算結果を返す。近い高さへの丸め、補間、浸水深の倍率変更はしない。Androidも同じ読込処理とJSONを使う。
- 採用計算はJS solver2.3、目標波高の校正許容差0.005m。計算領域は20m格子の96×109セルと96×93セル、共通表示範囲は1760×1280m（2026-11-04、従来の780×580mから約4.98倍）。西側の反射する切断境界を高地まで拡張し、南北を流出、東の湿潤部を加振境界とした。個々の結果が境界の検査に合格することを別途要求する。
- `expand_reporting_window.mjs <reviewed-pair.json> <primary.json> <secondary.json> <source-manifest.json> <original-bundle.json> <NEW_OUTPUT_DIRECTORY>` は既存72原本の生ハッシュを従来の配布結果と照合し、全36条件を変えずに表示範囲を探索する。旧表示枠を全部含み、共通計算領域の端から最低1セル離れた格子矩形を全探索し、固定した領域比較基準に合格する最大面積の矩形を選ぶ。選定後は既存の配布用検証処理で全36条件を再検査する。海や閾値未満の乾いた陸地は平均差の分母に加えない。計算結果を見た後の表示範囲選定であり、独立した予測精度検証ではない。
- これは指定波形・潮位・地形の条件比較。表示範囲外にも浸水が続く可能性があり、全浸水域・個別建物被害・実津波の予測精度を確定するものではない。

## 計算エンジンと旧公開版

PWA1.6.0／Android1.5.18は任意の高さをその都度計算する方式だった。以下の実行時計算処理は研究・監査用に保持するが、新しい保存結果版の公開ビルドには同梱しない。

- `build_browser_domain.py` は出典確認済みの地形をブラウザーのセル中心格子へ変換する。`build_browser_pair.py` は大きさの異なる2領域と中央の表示範囲を対応付け、検証前として出力する。
- `lab/web/tsunami-solver.mjs` は独立した有限体積浅水流モデル。数値方式と合成問題の検証は [BROWSER_SOLVER.md](BROWSER_SOLVER.md) を参照。ANUGAをそのままブラウザーへ移植したものではない。
- `lab/web/tsunami-compute.mjs` は指定値ごとに2領域で校正計算し、表示範囲内の陸域で水深差・浸水範囲を照合する。不一致や計算条件不成立はエラーとし、近い値や倍率変更で補わない。
- 旧公開版の表示範囲は熱海中心部780×580m、計算領域は1520×1700mと1520×1380mだった。新しい事前計算では上記の西側拡張・境界修正後の領域を用いる。
- 陸域の最大浸水深10cm以上を表示する。比較も同じ10cm閾値を用い、平均水深差0.1m以下・最大差0.5m以下・浸水範囲の重なり90%以上を要求する。これは領域の端への感度の確認で、実際の水深誤差の上限ではない。
- [領域比較と独立計算の検証記録](../../docs/superpowers/plans/2026-10-30-tsunami-boundary-validation.md) に合否と限界を残す。

**境界計算の修正:** 固定版3.3.10のFlather境界は、一括評価と単一辺評価の実装が一致しない。一括評価は外部水位が地盤より高い通常の海でも乾燥分岐を選ぶため、アダプターは公式の単一辺評価を明示的に呼び、特性波による境界値を使う。静止した水深10mの海へ外部水位0.2mを指定した初回の境界水位が0.1m、法線流量が `-sqrt(9.81*10)*0.1` となる独立試験を含む。旧結果の入力振幅を修正版へそのまま流用しない。結果の `solver.flather_evaluation` に使用経路を記録する。

`boundary_observation.py` はRK中間段階を含む全境界更新で内側・外側の実際の状態を観測する。DE1は起動時に辺の地盤を再構成し、境界の数値流束では外側地盤を内側地盤と同じ値にする。このため、元の地形節点の辺平均や、単一辺評価では更新されない `elevation.boundary_values` を水深の分母・基準に使わない。Froude数の検査はソルバーの有効水深下限1e−5m以上を対象とし、10cm未満の流れを見落とさない。元の地形辺平均は境界分類と出典記録に残す。`boundary-observations.json` をハッシュ付きで保存し、新しい監査はschema3、過去の結果の推定監査はschema2として区別する。

強制側が岬と海にまたがる実験では、`flather_stage` に明示的な `dry_edges: "reflective"` を指定できる。初期に海だった辺と隣接セルだけにFlatherを使い、それ以外は反射条件とする。指定しない場合は従来どおり全節点・隣接セルが初期に水中であることを要求する。この指定自体は人工境界問題の解決を意味せず、実際に濡れた切断境界や射流は不採用のままである。

北側の測量済み岬まで計算範囲を広げる追加実験では、`dry_edges: "transmissive"`も選択できる。初期の元地形辺平均と隣接セル標高がともに基準水位より0.001m以上低い辺だけにFlatherを使い、残る辺にはANUGAの流出境界を使う。後から濡れても分類は変えず、陸側に波の水位を強制せず、人工的な反射壁も作らない。この条件は外部状態を実測したことを意味しない。混在する辺の長さを監査に分けて記録し、流出辺のFroude数をFlatherの適用条件と混同しない。陸側の境界が実際の内側法線運動量をそのまま受け継ぐ試験と、海陸にまたがる静水保持試験を含む。

中央部だけを報告する追加実験では、東を初期に全面水中のFlather、西を高地の反射境界、南北をANUGAの`Transmissive_boundary`とする。南北へ浸水が続く場合は全浸水域を計算できたとは扱わない。[GeoClawの境界条件資料](https://www.clawpack.org/sphinx-versioning/bc.html)が説明する外挿境界の条件に従い、静水保持・中央部の境界種類比較・計算範囲比較を別々に確認する。斜めの波を完全に無反射にする条件ではなく、外部からの波がないことも水位・流量の記録だけで実証できない。監査の`supercritical_characteristic_boundary_observed`はFlatherに必要な常流条件を検査し、`supercritical_open_boundary_observed`は流出境界も含めた参考値である。射流が許される流出境界へ変更したことと、旧Flatherの異常を容認することを混同しない。流入・流出の法線速度と、初期に乾いていた開放辺への浸水長も記録する。

Native計算の水量収支は、初期・最終水量の差からANUGA自身の境界流量積分を引いた`mass_balance_error_m3`で確認する。外部から波を入れる計算では水量の増減そのものは誤差ではない。計算範囲比較が合格しても、実測津波への精度や20m地形格子の収束が確認されたことにはならない。

これは実地震の予測や実測津波に対する精度検証済みモデルではない。同じ「高さ3m」でも波の継続時間・方向・潮位・地形によって浸水範囲は変わる。

**2026-10-30の追加監査:** 既存の熱海3m・10m/20m格子はともに隣接セルの最大水位と境界標高から反射する陸側切断境界への浸水到達が推定され（境界水位の全時刻記録による証明ではない）、完全な浸水範囲を示す結果として不採用。原本は診断用に保持する。`result-reviews.json`はmanifestのSHA256へ結び付けた判定で、`build_map_data.mjs`は該当結果の再生成を拒否する。アダプターも不採用・境界異常の明記された原本を拒否する。既存の同梱・公開JSONをこの変更で自動削除したわけではない。新しい領域・境界で再計算するまでは旧結果を危険範囲の根拠にしない。

## 入口

- `height_request.py`: 任意の小数目標高をANUGA校正計算へ渡す独立検証用のオフライン入口。`python -m tools.tsunami.height_request scenario.json control.json NEW_OUTPUT --height 12.5 --maximum-forcing 30`。`--prepare-only`は計算要求JSONだけを出力し、計算済みとは扱わない。最大入力振幅は探索上限であり津波高そのものではない。条件と入力高さから要求IDを作り、実行前に再照合する。既存結果を上書きせず、近い高さへの丸め・浸水域の倍率変更はしない。アプリからは上記の共通ブラウザー計算を使う。

- `engine.py`: 検証済みシナリオの計算と変更不可の結果フォルダー出力。`python -m tools.tsunami.engine scenario.json output-directory`。
- `coastal.py`: `calibrate_coastal_height(scenario, control)`で海岸基準地点の高さを校正する。沖側に与えた振幅を、利用者が指定した海岸の高さとして表示しない。
- `terrain.py`: 出典URL・ハッシュ付きXYZ ZIPから明示した範囲の実在する格子点を読む。欠損補間・外挿・平らな海底の捏造はしない。
- `../../lab/web/tsunami-results.mjs`: 出力ファイルのハッシュ・三角形順・水深・校正残差を検証し、表示用GeoJSONへ変換する純粋関数。未計算の高さを近傍結果や補間結果で代用しない。
- `plot_result.py`: `python tools/tsunami/plot_result.py bundle-directory result.png`で監査用の最大浸水深図を出力。任意の描画依存`matplotlib==3.10.8`を別環境へ導入して使う。入力ファイルのハッシュを照合し、初期水位以上の地盤かつ到達閾値以上の深さだけを着色する。図はアプリの地図画面そのものではない。

依存は`requirements.txt`。プロジェクト全体のPython環境へ無断で混在させず、隔離環境で実行する。検証は`python -m unittest discover -s tools/tsunami -p 'test_*.py'`。

## 計算と保存の約束

### 過去の地図用固定データ（不採用・監査用）

以下は旧実装の生成経緯。保存結果版の配信ビルドではこの旧JSONと実行時ソルバーを除外し、全36条件の新しい検証済みセットを同梱する。旧結果へ戻す手順ではない。

`node tools/tsunami/build_map_data.mjs lab/web/tsunami-atami.json <10m-result-directory> <20m-result-directory>` で、原本のmanifestと内容ハッシュを照合して地図用GeoJSONを生成する。使った結果は `coastal-3m-10m-open-result` と `coastal-3m-20m-open-result`。旧境界の結果は含めない。最大深が1cm以上で初期水位以上の地盤だけを着色する。10mは896三角形、20mは193三角形。原本ハッシュ・基準点・実現波高・条件・範囲枠を一緒に保存する。

生成JSONをPWAとAndroid assetsに同一内容で同梱した。2026-10-30のSHA256は `779308f3b5a2ade45d78f7a737eaf533911a0152ccbdd2d06026f6785f33f87b`。色は浸水深0.01–0.5m、0.5–1m、1–2m、2–3m、3m以上の5階級。上端は次の階級に含む。背景地図の通信失敗でも結果の表示を止めない。最大深のみで、時刻別動画・任意の津波高への補間は実装していない。

### 原本の扱い

1. 標高基準、地形出典、初期水位、境界、粗度、波形、格子・時間条件をシナリオに残す。
2. 校正の初回は波を与えず、基準地点だけでなく領域内の全セルで静水が静止していることを確認する。
3. 試す振幅ごとに水の運動を計算し直す。浸水マスクを倍率で引き伸ばさない。
4. 指定基準地点の実現波高と目標値との差が許容値以内の場合だけ結果を採用する。
5. 最大浸水深・到達はソルバーの各ステップから集計する。間引いたアニメーション時刻だけから最大値を推定しない。
6. `write_bundle`は既存フォルダーを上書きせず、manifestを最後に保存する。未完了出力を計算済みとして配信しない。

`summary.json`の0は計算された0。到達時刻のnullは閾値へ達しなかったことを表し、未取得データや領域外の安全を表さない。`initially_dry`は初期水深が到達閾値より小さいセルであり、測量された行政上の陸海境界ではない。地図上の表示閾値と面積集計の陸域定義を併記する。

## 熱海での入力根拠と制約

最初の実地域範囲は熱海市中心部沿岸の780×580m。静岡県2019年ALBの公開XYZ格子を使用する。取得したファイルは1m間隔で、カタログ記載の一般的な解像度をそのままファイルの実間隔としない。

- [静岡県2019年点群データ](https://www.geospatial.jp/ckan/dataset/shizuoka-2019-pointcloud)
- [当該事業の報告書・ハイブリッドデータ成果品仕様](https://www.mlit.go.jp/toshi/tosiko/content/001481389.pdf): PDF107ページに事業・仕様、109ページにLP/ALB/MMS共通の調整点、117ページにJGD2011・TP・平面直角座標系VIIIの記載。各ZIP固有の標高証明書ではなく、事業仕様に基づく根拠。
- [気象庁の津波に関する説明](https://www.jma.go.jp/jma/kishou/know/faq/faq26.html): 沿岸での高さと陸上の浸水深・遡上を区別する。

2019年の標高に独自の一律補正を加えない。現在の潮位や特定地震の波形は取得・同定していない。PLATEAUの建物が存在することは、個別建物の耐波性や損傷モデルを計算したことを意味しない。20m/10mへの間引きは防潮堤や細い水路を失う可能性がある。

2026-10-30の試験では、単純な非加振側の流出境界で10m格子の静水が崩れる不具合を検出した。海側の開放境界と陸側の切断境界を明示的に分け、全領域の静水試験を再実施する。旧境界の20m結果と新境界の10m結果の差を、格子収束の比較として扱わない。計算実行記録・実現波高・比較の合否は、その実行で生成された結果と監査資料を参照する。
